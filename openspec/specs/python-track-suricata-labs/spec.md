## Requirements
### Requirement: A real, provenance-noted Suricata EVE corpus ships in plaintext-labs
The `plaintext-labs` companion SHALL provide a **real** Suricata EVE JSON corpus for Track 09 under
`python-for-security/` (submodule `plaintext/plaintext-labs`, repo `plaintext-security/plaintext-labs`).
The corpus MUST be generated by running Suricata over a real public PCAP (e.g. a
Malware-Traffic-Analysis.net infection capture or a Stratosphere/CTU dataset). The corpus MUST carry
**provenance**: the source PCAP's URL and a checksum, the Suricata version and ruleset (ET Open),
recorded in the lab so a learner can trace and reproduce it. Real Suricata/ET signature IDs MUST appear
in the alert events so the data anchors to real detection content.

#### Scenario: Corpus is real and traceable
- **WHEN** a contributor inspects the Track 09 lab data in `plaintext-labs`
- **THEN** the `eve.json` is genuine Suricata output over a named real PCAP, and the lab records the
  source URL + checksum, the Suricata version, and the ruleset used to generate it

### Requirement: The corpus is offline-reproducible at zero cost
The lab environment SHALL be reproducible at zero cost without redistributing third-party captures
improperly: it MUST commit a **small curated `eve.json` seed** (sufficient for the M02 clean/malformed
fixtures) and provide a `make`-time path that fetches the named PCAP (by URL + verified checksum) and
regenerates a larger `eve.json` with Suricata for the scale-oriented modules. A learner running
`make up` (and, where applicable, a documented generate step) MUST end up with real EVE data locally.

#### Scenario: One-command environment yields real EVE
- **WHEN** a learner runs `git clone` + `make up` (plus any documented generate step) in a Track 09 lab
- **THEN** real Suricata `eve.json` data is present locally — the small committed seed always, and the
  larger generated corpus where the module needs scale — with no paid resource required

#### Scenario: Malformed seed exercises the boundary
- **WHEN** the Module 02 lab runs its demo
- **THEN** the seed includes realistic malformed EVE lines (truncated/non-JSON, missing field,
  out-of-range severity, an unhandled `event_type`) so the typed boundary is shown rejecting real
  breakage, and heavy/generated artifacts are gitignored rather than committed

### Requirement: Demos, starter, and reference code read real EVE
Each Track 09 lab's runnable code in `plaintext-labs` SHALL be updated to operate on real EVE JSON:
`demo.py` reads/streams the real `eve.json` (not a synthetic CSV generator), `sift_starter/` reflects
the "AI helped" version that naively `.get()`s EVE fields, and `sift_reference/sift/*.py` provides the
finished EVE-based models (the M02 boundary model and the M06 core) as a **peek-after** reference. The
`Makefile` targets (`up`/`shell`/`demo`/`down`) MUST exercise the real substrate, and each lab's
`lab.md` copy MUST stay in sync with the `tracks/` source of truth.

#### Scenario: Demo contrasts trust vs. typed boundary on real EVE
- **WHEN** `make demo` runs in the Module 02 lab
- **THEN** the starter trusts or dies on the real malformed EVE lines while the typed boundary rejects
  each with a precise field-level reason — the same contrast as before, now on real Suricata output

#### Scenario: Reference stays peek-after, not the lab body
- **WHEN** a learner works a Track 09 lab
- **THEN** `sift_reference/` holds the finished EVE-based code for comparison after the learner's own
  attempt, and the lab body does not transcribe it

### Requirement: Lab validation path is preserved for later CI
The updated labs SHALL remain compatible with the deferred `.ci-demo` opt-in marker: the corpus
generation and demos MUST be designed to run on a Linux CI runner with Suricata available, so a later
backfill can mark a lab `.ci-demo` once `make up && make demo && make down` is green. This change does
not require adding `.ci-demo` now (Suricata runner still absent).

#### Scenario: Demos are runner-ready without being marked yet
- **WHEN** a maintainer later provisions a Suricata-capable Linux runner
- **THEN** the Track 09 lab demos can be exercised end to end and marked `.ci-demo` without redesign,
  because generation and demo steps assume only tooling a runner can install
